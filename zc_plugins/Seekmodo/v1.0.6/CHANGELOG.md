# Seekmodo Zen Cart connector — changelog

## v1.0.6
- **Bot-check backend selector (W6c, P1-14 Phase B).** `RemoteConfig::writeThrough()` now mirrors **eight** keys from the gateway's `tenant.snapshot` payload (was seven). New `bot_check_backend` field is normalised to one of `legacy` | `gateway` and written through to a new `NUMINIX_BOT_CHECK_BACKEND` configuration row. Anything else (typo, empty, missing) is dropped — the configuration row is left untouched, and the bot-check client falls through to its built-in `legacy` default.
- **Vendored bot-check client.** `catalog/includes/functions/numinix_bot_check_client.php` now ships INSIDE the plugin tree. Reads `NUMINIX_BOT_CHECK_BACKEND` and routes `classify` / `nonce.issue` / `nonce.verify` either at the standalone `bot-check.numinix.com` service (legacy) or at the gateway's `BotCheck\*` tools (`/v1/bot.classify`, `/v1/nonce.issue`, `/v1/nonce.verify`) when set to `gateway`. Default stays `legacy` so an in-place file deploy does NOT change behaviour until the operator opts in. Every helper inside is wrapped in `if (!function_exists(...))` so legacy tenants still shipping a sibling copy under `DIR_FS_CATALOG/includes/functions/` keep working — first-loaded wins.
- **Installer row.** `ScriptedInstaller` adds `NUMINIX_BOT_CHECK_BACKEND` (default `'legacy'`) to the Seekmodo Search configuration group with a `legacy | gateway` select.
- **Tests.** New `tests/W6cBackendSelectorTest.php` covers the 8-key write surface, gateway/legacy switching by the bot-check client, the legacy → gateway endpoint remap (`/v1/classify` → `/v1/bot.classify`), header scheme switching (`X-Numinix-*` ↔ `X-Seekmodo-*`), and the malformed-snapshot guard in `writeThrough`.

## v1.0.5
- **W6b consumption (default_mode + indexer_schedule).** `RemoteConfig::writeThrough()` now mirrors two more fields from the gateway's `tenant.snapshot` payload into the local `configuration` table: `default_mode` → `NUMINIX_SEEKMODO_DEFAULT_MODE` (used by the mode resolver as the fallback when `MODE` is unset) and `indexer_schedule` → `NUMINIX_SEEKMODO_INDEXER_SCHEDULE` (a cron-schedule enum used by the operator-side install script to render `/etc/cron.d/numinix-seekmodo-<tenant>`).
- **Mode resolver fall-through.** `numinix_seekmodo_mode()` now consults `NUMINIX_SEEKMODO_DEFAULT_MODE` when `NUMINIX_SEEKMODO_MODE` is empty / unset / not one of the four known values, before falling through to the literal `'off'` of last resort. Existing installs are unaffected because their `MODE` row is always set to one of `off|active|shadow|enforce`.
- **Indexer cron renderer.** New `tools/render_indexer_cron.php` (in the connector repo) translates the `indexer_schedule` enum (`hourly` / `every_4h` / `every_12h` / `daily` / `manual`) into a cron line. `tools/install_redline_connector.py` (in the seekmodo monorepo) writes the rendered line to `/etc/cron.d/numinix-seekmodo-<tenant>` on managed-mode installs.
- **Installer rows.** `ScriptedInstaller` adds `NUMINIX_SEEKMODO_DEFAULT_MODE` (default `'active'`) and `NUMINIX_SEEKMODO_INDEXER_SCHEDULE` (default `'daily'`) to the configuration group.

## v1.0.4
- **Conversion-event helpers (LTR P6).** New `numinix_seekmodo_mirror_add_to_cart($productsId, $opts)` and `numinix_seekmodo_mirror_purchase($productsId, $opts)` helpers (wrapping the internal `numinix_seekmodo_mirror_conversion($kind, ...)`). Connector hosts call these from Zen Cart's `NOTIFY_CART_ADD_CART_END` and `NOTIFY_CHECKOUT_PROCESS_AFTER_ORDER_CREATE_ADD_PRODUCTS` notifier hooks to ship graded relevance labels (click=1, add_to_cart=2, purchase=4) to the gateway. The trainer's `FeatureExporter` collapses click + AtC + purchase events on the same `(search_event_id, product_id)` into the strongest grade. Conversion events backfill `keyword` / `search_event_id` / filter context from `numinix_seekmodo_current_search_event()` when the caller doesn't pass them — appropriate for SERP-page add-to-cart buttons; cart/order-page calls should pass `keyword` explicitly when known.
- **Filter-context propagation (LTR P1).** The connector now forwards a structured `filters` map alongside the existing `filter_by` string on every `/v1/search` call. The gateway normalizes both inputs through `Search\FilterContext`, signs a stable `filter_hash`, and writes it onto the telemetry row. Trainer can now group clicks by `(query, filter_hash)` without a JSON-extract scan. See `services/mcp-gateway/sql/migrations/001_search_events_v2.sql`.
- **Click → search row linkage.** `numinix_seekmodo_run_search()` captures `meta.search_event_id` from the gateway response and stashes it on `$_SESSION['numinix_seekmodo_search_event']` so the page render can write the id into a hidden input. `numinix_seekmodo_mirror_click()`, `numinix_seekmodo_mirror_impression()`, and the new `numinix_seekmodo_mirror_serp_impression()` thread the id through to the gateway. The trainer joins click → search row directly (`search_event_id` FK) instead of guessing via session+keyword+time windows.
- **SERP impression beacon helper.** New `numinix_seekmodo_mirror_serp_impression($keyword, $productIds, $opts)` is the canonical call for "log the products visible on this rendered search page". Replaces ad-hoc usage of `numinix_seekmodo_mirror_impression()` for the SERP surface and threads the `search_event_id` + `filter_by` + `filters` + `surface='results'` defaults so the storefront's PHP template just calls the helper.
- **`numinix_seekmodo_current_search_event()` accessor.** Returns the most recent `{search_event_id, filter_by, filters, keyword}` triple for the current request. Storefront templates and JS-beacon emit paths use it as the single source of truth.

## v1.0.3
- **Storefront tuning forwarded to gateway** *(hot-fix added 2026-05-28)*. `_numinix_seekmodo_build_search_payload()` now forwards the storefront's `NUMINIX_TYPESENSE_TYPO_TOKENS_THRESHOLD`, `NUMINIX_TYPESENSE_DROP_TOKENS_THRESHOLD`, `NUMINIX_TYPESENSE_QUERY_BY` (+ aligned `query_by_weights`, `prefix`, `infix`), and the keyword/browse-mode `sort_by`. Without this the gateway fell back to `SearchDefaults::for('commerce')` (drop=1, typo=1) regardless of the tenant's admin-tuned values. Symptom on redlinestands.com: `keyword=automotive+rotisserie` returned 9 hits via gateway, 177 hits via the same Typesense backend called directly with the storefront's drop=10/typo=10. Per-field arrays only ship when their comma-count aligns with `query_by`'s — misaligned bundles would 400 against Typesense.
- **Generic filter pass-through.** Replaced the hard-coded `facets` body field (silently dropped by the gateway) with a runtime filter-mapping registry that builds a proper Typesense `filter_by` string from `$_GET`. Storefront integrators call `numinix_seekmodo_register_filter_mapping($urlParam, $field, $opts)` once at boot to declare each sidebar/attribute filter. Defaults now correctly map Redline's `?type=…` to `p_type` and `?capacity_by_lbs=…` to `capacity` so existing tenants don't regress. See `docs/FILTERS.md`.
- **Local-filter intersection helper.** New `numinix_seekmodo_apply_local_filter($remoteResult, $localIds)` lets a storefront intersect the gateway's product-ID list with a locally-computed filter set (for attribute filters that aren't indexed in Typesense, custom permission gates, etc.). The connector handles `total` recomputation and preserves rank order.
- **Typeahead through the gateway.** New `numinix_seekmodo_run_typeahead($q, $max, $opts)` helper and `numinix_seekmodo_typeahead_lib.php`. Routes autocomplete queries through `/v1/search` with prefix/infix tuning, records an `impression` event tagged `extra.surface='typeahead'`, and degrades to a `null` return so the storefront's existing direct-Typesense (or LIKE) fallback still works on gateway outage. See `docs/TYPEAHEAD.md`.
- **Surface-tagged click mirroring.** `numinix_seekmodo_mirror_click()` now accepts an `$opts = ['surface' => 'results']` argument (defaults preserved for v1.0.2 callers). New `numinix_seekmodo_mirror_typeahead_click()` wraps the same plumbing with `surface='typeahead'` so analytics can segment SERP clicks from autocomplete clicks. The gateway stashes the surface under `extra_json.surface` — no gateway schema change required.

## v1.0.1
- Connector now pages through gateway results (per_page=250 x 50 pages) so Zen Cart's local pagination sees every matching product, not just the first 10. Fixes 'more won't load' on storefronts where shoppers expected continuous scroll past page 1.
- Force IPv4 + relax connect timeout to 250-750ms (was 200ms) in Client.php and RemoteConfig.php — flaky CF IPv6 path on Redline web03 was tripping the breaker spuriously.
- Response normalizer handles the gateway's nested results.hits[*].document envelope in addition to the legacy flat {products,total} shape.
